## The regression baseline

`tests/regression/baseline.json` records what the system produces, generated by running it. It is committed, so regenerating it is a reviewable act: the diff shows which figures moved, and an unexplained movement is the finding.

| Recorded | Count | What is held fixed |
|---|---|---|
| Problem statements | 103 | every headline figure, population, result table, formula and rule |
| Tables | 5 | row counts, column order, dtype and null count of every column |
| Formulas | 18 | declared semantics and the value each worked example produces |
| Example queries | 533 | the analysis each one routes to, at 96.81% accuracy |

The suite is asymmetric by design. A figure that moves, a question that stops routing correctly, or a data-quality caveat that disappears is a failure. A new problem statement or a question that *starts* routing correctly is reported as a skip, not failed - the tests should not stand in the way of the system getting better, only in the way of it getting quietly worse.

### Caching

A repeated analysis costs **0.27 ms** against **28.4 ms** to recompute - roughly 107.1x. Correctness, not speed, is the hard part of a cache, and it is tested separately in `tests/regression/test_cache_safety.py`.

### The model, measured separately

Around a model call of known cost (250 ms, simulated), this system adds **14.4 ms** - prompt construction, parsing and validating the answer against the evidence. Mixing the API round trip into an end-to-end figure would report the network as this system's cost.
